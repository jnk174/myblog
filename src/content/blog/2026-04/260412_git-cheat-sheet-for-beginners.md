# 🎮 Git 핵심 명령어 정리 (개인 기록용)

새로운 기술을 배울 때 가장 기초가 되면서도 의외로 자주 잊어버리는 것이 Git 사용법입니다. Git은 제 작업물의 모든 순간을 기록해주는 '저장 포인트'이자, 언제든 과거로 돌아갈 수 있게 도와주는 든든한 타임머신과 같은 존재입니다.

나중에 제가 다시 찾아보기 위해, 그리고 Git이 낯선 순간이 올 때마다 꺼내 보기 위해 핵심 명령어들을 정리해 보았습니다.

---

## 🛠️ Git 기본 흐름 복습

작업을 하며 가장 많이 반복하게 되는 기본 3단계 흐름입니다.
1.  **add**: 저장할 파일을 장바구니에 담는 단계
2.  **commit**: 메시지와 함께 로컬 저장소에 영구히 기록하는 단계 (Save point)
3.  **push**: 로컬의 기록들을 원격 저장소(GitHub)로 안전하게 전송하는 단계

## 🔍 핵심 개념 이해: Commit vs Push vs Merge

상황에 따라 헷갈릴 수 있는 세 가지 핵심 개념을 제 방식대로 정리해 보았습니다.

- **Commit (내 컴퓨터에 저장)**: 작업 중인 내용을 하나의 '버전'으로 확정 짓는 것입니다. 게임으로 치면 **세이브 포인트**를 만드는 것과 같습니다. 아직은 제 컴퓨터 안에만 존재합니다.
- **Push (서버로 전송)**: 내 컴퓨터에서 만든 Commit(세이브 포인트)들을 GitHub 같은 **원격 서버에 업로드**하는 과정입니다. 이제 다른 사람들도 제 작업물을 볼 수 있게 됩니다.
- **Merge (작업 합치기)**: 서로 다른 두 가지 작업 내역을 **하나로 합치는 것**입니다. 예를 들어, 새로운 기능을 테스트하던 '실험용 기록'을 '메인 기록'에 합치고 싶을 때 사용합니다.

## 📜 깃(Git) 핵심 명령어 요약

### 1. 초기 설정 및 복제 (Initialization)

| 명령어 | 설명 | 비고 |
| :--- | :--- | :--- |
| `git init` | 현재 폴더에서 Git 저장소 시작 | 새로운 프로젝트를 시작할 때 실행합니다. |
| `git clone [주소]` | 원격 저장소의 내용을 그대로 복제 | 기존의 프로젝트를 가져올 때 사용합니다. |

### 2. 로컬 작업 관리 (Local)

| 명령어 | 설명 | 비고 |
| :--- | :--- | :--- |
| `git status` | 현재 파일들의 상태 확인 | 작업 중 수시로 확인해야 할 필수 명령어입니다. |
| `git add [파일명]` | 특정 파일을 스테이징 영역에 추가 | |
| `git add .` | 모든 변경 사항을 한꺼번에 추가 | |
| `git commit -m "메시지"` | 메시지와 함께 새로운 커밋 생성 | 어떤 작업을 했는지 구체적으로 적는 습관을 들입니다. |

### 3. 원격 저장소와 동기화 (Remote)

| 명령어 | 설명 | 비고 |
| :--- | :--- | :--- |
| `git push` | 로컬 커밋들을 서버로 업로드 | |
| `git pull` | 서버의 최신 내용을 가져오기 | 다른 환경에서의 작업 내용을 불러올 때 사용합니다. |

### 4. 과거 기록 확인 및 이동 (History)

| 명령어 | 설명 | 비고 |
| :--- | :--- | :--- |
| `git log` | 지금까지의 모든 커밋 기록 확인 | |
| `git checkout [id]` | 특정 시점의 코드로 일시 이동 | 다시 현재로 돌아올 때는 `git checkout -`를 씁니다. |

### 5. 브랜치 및 머지 (Branch & Merge)

| 명령어 | 설명 | 비고 |
| :--- | :--- | :--- |
| `git branch [이름]` | 새로운 브랜치(가지) 생성 | 독립적인 공간에서 새로운 시도를 할 때 씁니다. |
| `git checkout [이름]` | 해당 브랜치로 이동 | 작업을 이어나갈 공간을 전환합니다. |
| `git merge [이름]` | 현재 브랜치에 다른 브랜치 합치기 | 테스트가 끝난 코드를 메인 기록에 통합할 때 씁니다. |

## 💡 개인적인 Git 사용 원칙

- **`git status` 생활화**: 제가 지금 어떤 상태에 있는지 파악하는 것이 실수를 줄이는 가장 빠른 길임을 깨닫고 있습니다.
- **직관적인 커밋 메시지**: "update" 같은 무의미한 말보다는, 미래의 제가 봐도 이해할 수 있도록 명확하게 기록하겠습니다.
- **주기적인 Pull**: 작업 시작 전에는 항상 최신 상태를 유지하여 충돌을 미연에 방지하고자 합니다.
